# Project Rules & Workflow Guidelines

## 1. Git Branching Strategy
- **New Feature Branching**: Every time a new feature is created, always create a new branch from `main`.
- **Branch Naming Standard**: `feature/<feature-name-in-english>` (e.g., `feature/user-auth`, `feature/data-pipeline`).

## 2. Directory & Scope Structure
- Primary development location: `frontend` and `backend` directories.
- Guidelines and design references location: `docs/guide_cho_ca_nhom/`.

## 3. Team Guidelines & Documentation References
- **`docs/guide_cho_ca_nhom/TECHNICAL_CODING_GUIDELINES.md`**: Follow all technical standards (Clean Architecture for backend, exception handling, Type Hints 100%, max function length 30 lines, ruff linting, DTO rules, etc.).
- **`docs/guide_cho_ca_nhom/DAILY_WEEKLY_CHECKLIST.md`**: Follow daily routines.
- **`WORKLOG.md`**: Record completed work daily.
- **`JOURNAL.md`**: Document daily/weekly technical decisions and lessons learned.
- **`docs/guide_cho_ca_nhom/data_flow.md`**: Reference system design data flow diagram.
- **`docs/guide_cho_ca_nhom/database.md`**: Reference database design schema.
- **`docs/guide_cho_ca_nhom/usecase.md`**: Reference agreed MVP use cases.
